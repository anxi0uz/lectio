# Инструкции для AI-агентов

## Начало работы

1. Прочитай `docs/ai/status.md` — что сделано, что в работе, что дальше.
2. По задаче загляни в остальное из `docs/ai/`: `project.md` (цели, ТЗ, сроки,
   команда), `architecture.md` (как устроено и как запускать), `decisions.md`
   (почему так), `gotchas.md` (на что уже наступали).

Этой папке можно доверять: её ведут агенты по ходу работы, и она точнее
истории чата, которая обрезается при сжатии контекста. Если видишь, что в ней
что-то расходится с кодом, — верь коду, исправь документ и скажи об этом
пользователю.

## Обновляй docs/ai

- **`status.md` — после каждого законченного куска работы**: что сделано,
  что закоммичено, что нет, что не проверено, что следующее. Перед тем как
  сжимать контекст или заканчивать сессию — обязательно.
- Новое решение с причиной → `decisions.md`.
- Новая неочевидная проблема и обход → `gotchas.md`.
- Поменялись структура, запуск, соглашения → `architecture.md`.
- Поменялись цели, сроки, договорённости с пользователем → `project.md`.

Пиши коротко и фактами, по-русски, с абсолютными датами. Устаревшее исправляй
или удаляй, не оставляй противоречий. Не копируй туда код и списки
эндпоинтов. Секреты (ключи, токены) не записывай никогда.

## Работа в репозитории

- Бэкенд пиши в стиле существующего кода (он повторяет `~/projects/linkup`):
  модули `router/service/schemas/exceptions`, сервисы только `flush`,
  аргументы по одному на строку, комментарии по-английски и только «почему».
- Перед сдачей: `uv run ruff check .`, `uv run ruff format --check .`,
  `uv run pytest`, `uvx --from basedpyright basedpyright --level error src tests`;
  для фронта `npm --prefix frontend run typecheck` (или `build`).
- Видимые изменения проверяй в браузере сам, не перекладывай на пользователя.
- Коммиты и пуш — только по прямой просьбе пользователя. Стиль сообщений:
  conventional commits.
- Обвязку хостинга во `frontend/` (`worker/`, `scripts/`, `.openai/`,
  `tests/sites-worker.test.mjs`) не трогай.
