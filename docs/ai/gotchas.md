# Грабли

Каждая уже стоила времени. Перед похожей работой — пробежать глазами.

## Окружение и процессы

- **`pkill -f` / `pgrep -f` убивают собственную shell-команду**, если шаблон
  встречается в её тексте (exit 144). Убивать по PID: `pgrep -f "python -m lectio.worker$"`
  с якорем `$`, потом `kill <pid>`. В zsh `kill $(pgrep …)` с переводом строки
  внутри даёт «illegal pid» — передавать PID через пробел.
- **После перезагрузки ПК контейнеры остановлены** (Postgres, Redis, тестовые).
  Симптом: 500 на логине, `ConnectionError … 6379`. Лечение: `podman compose up -d`
  и `podman compose -f compose.test.yaml -p lectio-test up -d`.
- **Воркер сам не стартует.** Лекции висят «В очереди», пока его не запустить.
- **Vite залипает на старой версии модуля** после серии правок (ошибка про
  несуществующий экспорт, хотя в исходнике его нет). Лечение — перезапуск
  dev-сервера, не перезагрузка страницы.
- **Панель браузера Claude скрыта → скриншоты рвутся при прокрутке**: страница
  не перерисовывается. Проверять через `javascript_tool` / `read_page`.
- **Email на `.test` не проходит валидацию** (зарезервированный домен).
  Для тестовых аккаунтов — `example.com`.

- **Официальные образы MinIO недоступны** (`minio/minio`, `quay.io/minio/minio`
  — denied/unauthorized, даже старые теги). Берём `docker.io/pgsty/minio`
  с закреплённым тегом; в образе есть `curl` и `mc` для healthcheck.
- **Ключ подписи S3 включает хост**: ссылку для браузера подписывает
  отдельный клиент на `S3_PUBLIC_ENDPOINT`; регион задан явно, иначе SDK
  ходит в сеть за регионом при каждой подписи.

- **Тесты читают `.env`**: всё, что там меняет поведение (например,
  `STORAGE_BACKEND=s3`), надо явно перебить в `tests/conftest.py`.

## GPU и модели

- **6 ГБ:** рабочий стол ~1–1.5 ГБ, Discord ещё ~0.5 ГБ (из-за него модель
  уходит на CPU на 8–17%). Пик при «чат + сразу обработка» ~4.8 ГБ.
- **`release_*` не освобождает память, если на модель есть локальная ссылка**
  (переменная в `finally`). Вызывать модель без локальной переменной.
- **BGE-M3: `.half()` после загрузки оставляет fp32-копию в кеше CUDA** —
  грузить сразу `model_kwargs={"dtype": torch.float16}`.
- **faster-whisper 1.2.1 несовместим с новым PyAV** (`metadata_errors`) — ему
  передаётся уже декодированный WAV-массив (`read_pcm_wav`).
- **CTranslate2 находит cuBLAS/cuDNN только если раньше импортирован torch.**
- **Ollama держит модель 5 минут** после запроса — Whisper при этом падает
  по памяти; поэтому воркер шлёт `keep_alive: 0` перед своими этапами.
- **RAM процессов выглядит пугающе, но это нормально**: llama-server ~2.6 ГБ
  — это mmap файла модели (кеш), воркер не отдаёт память ОС после выгрузки.
- **Маленькая модель отвечает «в лекциях не было»**, если фрагменты на другом
  языке — в промпт добавлено «переводи смысл».
- **`systemctl edit` в nano**: Ctrl+O требует Enter, иначе ничего не сохранится.
  Надёжнее `printf … | sudo tee …/override.conf` + `daemon-reload`.

## Фронт

- **Глобально `refetchOnWindowFocus: false`** (`App.tsx`), а опрос по
  умолчанию спит в фоновой вкладке → страница «не обновлялась». У лекции
  `refetchIntervalInBackground: true` и инвалидация по смене статуса в
  `useLecture`. Любое новое действие, ставящее задачу воркеру, должно сразу
  менять статус лекции в API, иначе фронт не начнёт опрос.

## Библиотеки

- redis-py 8: socket timeout 5 с → BRPOP с таймаутом ≥5 падает. У нас 2 с.
- SQLAlchemy 2.1: нужен extra `[asyncio]` (greenlet); `Result.tuples()` и
  `Row.tuple()` устарели — строки распаковываются напрямую;
  `Select[A, B, C]`, а не `Select[tuple[A, B, C]]`.
- Alembic autogenerate создаёт безымянные FK → откат ломается. Давать имена.
- React вешает `onWheel` пассивным — для `preventDefault` нужен нативный
  слушатель `{ passive: false }`.
- yt-dlp: при обрыве оставляет `video.fNNN.mp4(.part)`; без фильтра по имени
  можно взять видеодорожку без звука за готовое видео.
- YouTube через VPN качается в разы медленнее и рвёт соединение; с IP
  датацентров (VPS) часто требует «подтвердить, что не бот».
